# 三道题、四个模型：一次横评的原始材料

这个仓库放的是一次模型横评的全部原始材料：三道题，四个模型，每个模型每道题只跑一次，交卷之后没有人工返工。配套的文章发在公众号上（链接待填）。

## 目录结构

```
tasks/     三道题的题目原文，和题目要用的输入文件
models/    四个模型交出来的原始答案，以及它们自己写的交付说明
scoring/   六个方面的分数表、总榜，和 8 张首屏截图
```

## 三道题

1. **图纸变房间。** 给模型一张房子的平面图，让它把图里的墙、门、窗读出来，生成一个可以在里面摆家具的三维房间，最后把房间导出成 Unity 和 UE5 都能打开的文件。题目原文在 `tasks/task-1-brief.md`。
2. **接手烂后端。** 给模型一份失联外包留下的订单服务代码，让它判断这个服务明天能不能上线收钱，并且把必须改的地方改出来。题目原文在 `tasks/task-2-brief.md`。
3. **场景渲染。** 让模型在火箭发射和火山喷发里二选一，做出一个打开就好看的场景。题目原文在 `tasks/task-3-brief.md`。

题目原文里写的是评测当时的相对路径（每个模型目录下面有一份 `_shared/`），仓库里把三个输入文件统一放在了 `tasks/assets/` 下面。

## 四个模型

`models/` 下面有四个目录：`grok-4.7`、`opus-5.5`、`deepseek-v4.1`、`qwen4-preview`。每个目录的结构一样：

- `answers/1/`：图纸题的答案，是一个可以直接打开的网页。
- `answers/2/`：后端题的答案，包括 `FINDINGS.md`（体检报告）和 `patched/orders.js`（改好的代码）。
- `answers/3/`：渲染题的答案，是一个可以直接打开的网页。
- `DELIVERY.md`：这个模型自己写的交付说明，里面包括它承认没做完的部分。

网页里带的 `out.glb`、`out.obj`、`out.mtl` 是模型自己导出的样例文件。

## 怎么打开这些页面

大部分页面可以直接双击打开。用本地服务器更稳，因为浏览器打开本地文件的时候，不允许页面读取同一个目录里的文件：

```
cd models/qwen4-preview/answers/1
python -m http.server 8000
```

然后在浏览器里打开 `http://localhost:8000/`。

有一个例外：Opus 的页面通过 CDN 加载 three.js 0.160，需要联网；另外三个模型的 three.js 都放在本地的 `vendor/` 目录里。

## 分数怎么来的

每道题满分 100 分，分数按六个方面计算：完成度、一次成功率、工程结构、界面与呈现、时间、资源消耗。三道题里，这六个方面的分值不一样，具体的分值表和每个模型的分数在 `scoring/scores.md` 里。

总分是把三道题的分数按 4:3:3 的比例加起来算的。

总榜：Opus 5.5 拿到 86.3 分，千问4预览版拿到 86.0 分，DeepSeek V4.1 拿到 84.6 分，Grok-bot 4.7 拿到 78.7 分。

## 边界

- 这些分数是我一个人打的主观分，题目是我自己出的，每道题只让模型跑了一次，六个方面各占多少分也是我定的。它更像一份认真的试用记录，不是专业测评机构做的那种测试。
- 这次测试是受邀完成的：邀请方提供了千问4预览版的提前访问，并且审阅了我在公众号发布的文章。本仓库只放原始材料和分数，不把结论放在这里。
- 截图都是首屏的静态图，渲染类的产出动起来之后差别更大。
