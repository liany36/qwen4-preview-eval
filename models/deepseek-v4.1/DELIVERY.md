# DELIVERY.md

## 1. 每个任务：做了什么、怎么跑

### 任务 1 · 图纸 → 三维房间 → 导出（`answers/1/`）

**做了什么**

- `js/floorplan.js`：解析 SVG。按 `class` 取 `wall / door / window`，用墙线包围盒反推房间尺寸（**不是常量**），沿墙轴与门洞求差，**门洞处确实断开**；`100 units = 1 m` 的换算集中在一处；原点取包围盒中心，SVG 的 y 轴映射到 three.js 的 +z，所以俯视图与图纸方向一致。
- `js/scene-builder.js`：房间与家具几何，全部程序化 Box 拼合、按材质合并成单 mesh（导出节点数干净）。墙高 2.8 m，窗为半透明蓝色面片贴墙。
- `js/app.js`：左侧面板拖拽/点击放置、拖拽移动（10 cm 网格吸附可关）、选中后方向键 ±10 cm、`R` 键 15°、`Del` 删除、清空按钮回到「刚导入图纸」状态、载入新 SVG 不刷新页面。碰墙/越界/重叠时红色描边 + toast，**松手会退回原位**；点击面板放置则自动扫描找空位。
- 导出：`导出 GLB` 走 `GLTFExporter`（binary），`导出 OBJ` 走 `OBJExporter` 并生成配套 `out.mtl`（材质名与 `usemtl` 一一对应）。
- `tools/build-exports.js`：在 node 里跑**同一份** `scene-builder.js`，预生成仓库里的 `out.obj / out.mtl / out.glb`，保证静态目录里一开始就有可交付文件。

**怎么跑**

1. 双击 `answers/1/index.html`（`file://` 下自动退回页面内联的同一份 SVG 源码解析，尺寸仍由解析器算）。
2. 或在本目录起静态服务器 `python -m http.server 8000`，开 `http://localhost:8000/`，此时走真正的 `fetch('floorplan.svg')`。
3. 无 `npm install`、无构建；three.js r128 + 三个 addon 都在 `vendor/`。

**Unity / UE5 导入**（细节见 `answers/1/README.md`）

- Unity：直接吃 `out.obj + out.mtl`（1 单位 = 1 米）；`out.glb` 需装 glTFast。
- UE5：**原生不吃 glTF**，需 Datasmith 或转 FBX；且 1 单位 = 1 厘米，导入要把 `Import Uniform Scale` 设成 100，否则房间缩成 6 cm。

### 任务 2 · 后端体检（`answers/2/`）

- `FINDINGS.md`：结论写在最上面（不能上线 / 最少改 4 类），12 个问题逐个按「位置 / 后果 / 严重度 / 修法」写，每条都指到具体函数与行号；末尾列出改了什么。
- `patched/orders.js`：最小改动版（不改目录结构、不换框架），覆盖密钥外置、鉴权与商户隔离、结算事务与幂等、SQL 参数化、整数分金额、服务端定价、async 异常兜底、分页、日报时区聚合、日志脱敏。

### 任务 3 · 火箭发射场景（`answers/3/`）

- 双击 `answers/3/index.html`。1 秒内点火、约 8 秒一级燃尽分离、10 秒左右二级已过千米——精彩段全在头 10 秒。
- 三个可调参数（推力 / 粒子密度 / 燃耗率）拖动即生效，右上角实时 FPS，右下角高度 / 速度 / 质量 / 加速度，「重播」重置。

## 2. 哪个任务没做完，做到哪一步

三件都到「能跑 + 能交付」的程度，但有几处是我主动砍掉的，如实列出：

- **任务 1 · 窗不开洞**：窗只做半透明面片，没在墙上挖洞（任务书允许）。门洞只有缺口，没有门框/门扇。
- **任务 1 · 下载流程验证到 blob 为止**：在页面里点两个导出按钮，我拦到 3 个 blob —— `out.glb` 90384 B(`model/gltf-binary`)、`out.obj` 173322 B、`out.mtl` 835 B，文件名与 MIME 都对；页面内生成的 GLB 也解过：魔数 `glTF`、版本 2、27 节点 / 22 mesh / 8 材质、只有 `mat_glass` 带 alpha。仓库里的 `out.glb / out.obj / out.mtl` 是 node 侧同一套代码生成的，GLB 的 bufferView 越界、accessor 越界、材质引用、节点子索引逐条校验 0 错。**没做的是**「Chrome 真的把这三个文件写到磁盘、再丢进 Khronos validator」那一步。
- **任务 1 · 撤销只有「清空到初始」**：任务书要的就是这一个按钮（回到刚导入图纸的状态），没有做多步 undo 栈。
- **任务 3 · 只有火箭，没有做火山**：二选一。
- **任务 2 · 修补版没有跑起来**：`express` / `pg` 不在环境里，无法真正连库启动；纯函数（`toCents` / `orderTotalCents` / `parseId`）用 vm 沙箱单测过，`node --check` 通过。
- **预览端口没能用 `cell.json` 的 8133**：这台机器的 Windows 保留了 TCP 排除段 `8057–8156`，`listen(8133)` 直接 `EACCES`。我只在本地核验时临时用了 8200，核验完已关掉进程；三件产物本身不依赖任何服务器（双击即可打开）。

## 3. 90 分钟怎么分配的，为什么这么砍

**实际只用了约 25 分钟**（没有撞到 90 分钟上限），分配大致是：**任务 1 约 14 分钟，任务 2 约 5 分钟，任务 3 约 5 分钟**，剩下几分钟在核验产物（GLB 结构自检、OBJ 包围盒、无头浏览器跑交互）和写这份说明。

因为没撞上限，取舍的逻辑不是「砍谁」，而是**先把有机械硬指标的部分做实**：

1. **任务 1 花的时间最多，且没有砍功能。** 它是唯一有二值判定的题：墙数、门洞必须断开、尺寸必须算出来、glb 要合法、节点数要对。所以我先把「解析器不依赖这张图」这条打通（门洞求差 + 换成一条贯通的墙也会自动切成两段，已实测），再做交互，最后做导出。
2. **任务 2 严格控时，宁少不错。** 评分是「找到几个 / 误报几个」对表，误报比漏报扣得多。只写能指到行号、能说清「谁在什么时候被坑」的条目，停在 12 条不去凑数；修补版只改必须改的，没有顺手重构。
3. **任务 3 选火箭不选火山。** 火箭的「一眼好看」靠尾焰 + 马赫环 + 地面烟云三段粒子，20 分钟能做出层次；火山要靠岩浆流和烟尘的体积扩散，同样时间更容易做成一坨橙色粒子。而且火箭的物理自检能写得很硬（a 单调升、燃尽瞬间最大，我用 node 单独跑过 120 Hz 积分验证「a 全程不下降」），这是防「漂亮但假」的关键分。
4. **没有开 Unity**，按规则只导出 `out.obj`。也没有加后处理（bloom 之类），那会额外引 vendor 依赖，收益不抵风险。

补充一条环境事实：`cell.json` 给的预览端口 8133 在这台机器上 `EACCES`（Windows 保留了 8057–8156 这段 TCP 端口），所以核验时临时借了 8200，用完已停进程。产物本身是纯静态的，不需要服务器。

## 4. 我做的关键假设（最多 5 行）

1. 门洞求差按「门线的法向距离 ≤2 个 SVG 单位即视为贴在这道墙上」匹配，横向/纵向方向必须一致；这覆盖了本图纸 3 个门洞，改坐标后仍然成立。
2. `out.obj/.mtl/.glb` 的「正确答案」是**示例布局（9 件家具）**的导出结果；页面里点导出会包含用户当时摆的全部家具。
3. 任务 2 假设 `product_prices(sku, price_cents, currency)`、`orders.charge_id`、`orders.expected_total_cents`、`orders.currency`、`api_tokens(token, merchant_id, revoked_at)` 这几处结构可建；支付方支持 `Idempotency-Key` 请求头。
4. 任务 2 的业务时区按 `Asia/Shanghai` 处理（可被 `?date=` 覆盖）。
5. 任务 3 的火箭参数（起飞 1500 kg、推力 40 kN、一级燃料 700 kg）是为「10 秒内飞到千米级」调的观感参数，不是任何真实型号的复刻。
