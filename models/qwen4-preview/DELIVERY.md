# DELIVERY · 格子 D

## 1. 每个任务：做了什么、怎么跑

- **任务 1**（`1/`）：SVG 解析 → 3D 房间（墙 2.8 m、门洞切墙、半透明窗、房间名标签）→ 家具面板拖放（桌/椅/柜，程序化几何）→ 拖动吸附 0.1 m、方向键 ±10 cm、R 转 15°、Delete 删除 → 撤销清空 → 导出 glb/obj+mtl（附真实导出的 `out.glb`/`out.obj`/`out.mtl`，含 3 件家具）。跑法：本目录起任意静态服务器开 `index.html`，或双击（file:// 用内嵌图纸副本，改图纸走「载入新图纸」）。详见 `1/README.md`。
- **任务 2**（`2/`）：`FINDINGS.md` 10 个问题（4 致命 5 严重 1 一般），开头三行给出上线判断；`patched/orders.js` 是最小修补副本，`node --check` 通过。跑法：`DATABASE_URL=... PAYMENT_KEY=... node patched/orders.js`（需 express+pg，与原文件一致）。
- **任务 3**（`3/`）：火山喷发，单 HTML + volcano.js，打开即喷、6 秒爆发周期、FPS 角标、4 个实时滑杆、重置按钮、100 字物理自检（页面内 + README）。双击即开，three.js 本地化无 CDN。

三个任务的核心验收项都做完。未做的边角：任务 1 的 unity.png（brief 允许评分人自导）；碰撞只警告不阻止放置；撤销是清空而非逐步 undo（brief 定义如此）。任务 3 没做后处理 bloom（加性混合粒子已够亮，预算内不追）。

## 3. 90 分钟怎么分配的，为什么这么砍

实际约 35 分钟：任务 1 ≈ 20 分钟（含浏览器实测拖拽/导出/改坐标重解析），任务 2 ≈ 8 分钟，任务 3 ≈ 7 分钟。没触发砍取舍——因为任务 1 选了经典脚本版 three（r147）一次性解决 file:// 兼容，省掉模块加载的坑；任务 2 只修必须项不重写；任务 3 选火山（粒子系统比火箭级间分离省时间）。若任务 1 超时，预案是先保任务 2（支付判断是老板明天要的唯一决策，文字交付边际成本最低），任务 3 砍到"能喷 + FPS + 一个滑杆"保底。另：8134 端口被 Windows 保留段（8057–8156）占用，预览临时用了 8157——产物是纯静态文件，不依赖该服务器。

## 4. 我做的关键假设（最多 5 行）

1. 支付网关 amount 按最小货币单位（分）收——这是 v2 charge API 的行业惯例；若实际按元收，问题 3 的修法反向，但单位不统一这个 bug 本身成立。
2. expected_total 与 price 同口径（元），浮点误差用 0.005 容差兜底。
3. 业务日按服务器本地时区（部署在国内即北京时间）。
4. 墙厚图纸说忽略，视觉/碰撞取 0.12 m 中心线厚度。
5. file:// 双击打开时浏览器禁 fetch 本地文件，故内嵌同源图纸副本兜底；静态服务器下永远读外部 SVG。
